# Requirements Document: Exam Template Selection and Injection

## Introduction

This feature enables enseignants (teachers) to generate AI-powered exams using predefined templates from the exam bank. Currently, the AIGenerator component generates exam content without template selection, resulting in plain JSON structures. This feature introduces a structured workflow where teachers first select a template, fill in header information, generate AI content, and have that content automatically injected into the template's structure while preserving formatting and layout.

The system will maintain template integrity (logos, institutional headers, sections, formatting) while dynamically populating exam-specific content (title, subject, duration, questions, etc.) generated by AI.

## Glossary

- **Enseignant**: Teacher/instructor user role
- **Template**: A predefined Word document structure stored in the exam bank with fixed layout, logos, headers, and placeholder sections
- **Template_Bank**: Collection of available exam templates managed by administrators
- **Header_Information**: Metadata fields that customize a template (title, subject, department, level, duration, etc.)
- **AI_Generator**: Service that generates exam content (questions, sections, exercises) using AI
- **Template_Injector**: Service that maps AI-generated content into template placeholders
- **Exam_Content**: AI-generated questions, exercises, and sections in JSON format
- **Template_Structure**: Fixed layout elements in a template (logos, institutional info, sections, formatting)
- **Placeholder**: Named location in a template where dynamic content will be inserted
- **Template_Type**: Category of template (final, cc/control, rattrapage/makeup)
- **Template_Style**: Layout variant (long, court/short)
- **Template_Language**: Language variant (Français, Arabe, Bilingue)
- **Draft_Exam**: Temporary exam record before final export
- **Exam_Bank_Item**: Finalized exam stored in the exam bank with file and metadata

## Requirements

### Requirement 1: Template Discovery and Selection

**User Story:** As an enseignant, I want to browse and select an exam template from the exam bank, so that I can use a predefined structure for my AI-generated exam.

#### Acceptance Criteria

1. WHEN the enseignant navigates to the exam generation workflow, THE AIGenerator_UI SHALL display a template selection interface before showing the AI generation form
2. WHEN the template selection interface loads, THE System SHALL retrieve all active templates from the Template_Bank and display them in a list or grid view
3. WHEN templates are displayed, THE System SHALL show for each template: template name (nom), type (final/cc/rattrapage), language (Français/Arabe/Bilingue), style (long/court), and a preview thumbnail
4. WHEN the enseignant clicks on a template, THE System SHALL display a detailed preview showing the template's structure, header fields, sections, and formatting
5. WHEN the enseignant selects a template, THE System SHALL store the selected template ID and make it available to subsequent workflow steps
6. IF no templates are available, THEN THE System SHALL display a message indicating that templates must be created by an administrator before proceeding
7. WHEN the enseignant wants to change templates, THE System SHALL allow template reselection at any point before final exam generation

### Requirement 2: Header Information Collection

**User Story:** As an enseignant, I want to fill in exam-specific header information, so that the template is customized with my exam details.

#### Acceptance Criteria

1. WHEN a template is selected, THE System SHALL display a form with header fields extracted from the selected template's metadata
2. THE Header_Form SHALL include fields for: exam title (titreExamen), subject (matiere), department (departement), level (niveau), duration (duree), academic year (anneeUniversitaire), semester (semestre), exam date (dateExamen), total points (noteTotale), and authorized documents (documentsAutorises)
3. WHEN the form loads, THE System SHALL pre-populate fields with values from the selected template as defaults
4. WHEN the enseignant modifies a field, THE System SHALL validate the input and provide real-time feedback for invalid entries
5. WHEN the enseignant submits the header form, THE System SHALL store the header values and pass them to the AI generation step
6. IF required fields are empty, THEN THE System SHALL prevent form submission and highlight missing fields with error messages
7. WHEN the enseignant wants to modify header information, THE System SHALL allow editing at any point before final exam generation

### Requirement 3: AI Content Generation with Template Context

**User Story:** As an enseignant, I want to generate AI exam content while providing template and header context, so that the AI understands the exam structure and constraints.

#### Acceptance Criteria

1. WHEN the enseignant proceeds to AI generation after selecting a template and filling header information, THE AIGenerator_Service SHALL receive the selected template ID and header values as context
2. WHEN generating exam content, THE AI_Generator SHALL consider template constraints: template type (final/cc/rattrapage), style (long/court), and language (Français/Arabe/Bilingue)
3. WHEN the enseignant specifies generation parameters (subject, level, duration, number of questions, question types), THE AI_Generator SHALL incorporate these with the template context to generate appropriate content
4. WHEN AI generation completes, THE System SHALL return exam content in JSON format with sections, exercises, and questions structured according to the template's expected format
5. WHEN exam content is generated, THE System SHALL preserve all header information (title, subject, department, level, duration, etc.) for injection into the template
6. IF AI generation fails, THEN THE System SHALL return a descriptive error message and allow the enseignant to retry with modified parameters

### Requirement 4: Template Injection Service

**User Story:** As an enseignant, I want AI-generated content to be automatically injected into the selected template, so that I get a properly formatted exam document.

#### Acceptance Criteria

1. WHEN the enseignant confirms AI-generated content, THE Template_Injector_Service SHALL receive: selected template, header information, and AI-generated exam content
2. WHEN injection begins, THE Template_Injector SHALL map AI-generated sections and exercises to template placeholders
3. WHEN injecting header information, THE Template_Injector SHALL populate template fields: titreExamen, matiere, departement, niveau, duree, anneeUniversitaire, semestre, dateExamen, noteTotale, and documentsAutorises
4. WHEN injecting exam content, THE Template_Injector SHALL preserve template structure: logos, institutional headers, section layouts, and formatting
5. WHEN injecting questions, THE Template_Injector SHALL map question text, type, points, and options into template exercise sections while maintaining formatting
6. WHEN the template includes optional sections (zoneNomPrenom, zoneGroupe, blocNote, blocCommentaires, blocSignature, blocRemarques), THE Template_Injector SHALL include or exclude these sections based on template configuration
7. WHEN injection completes, THE System SHALL generate a Word document (.docx) with all content properly formatted and positioned
8. IF injection encounters missing or incompatible content, THEN THE System SHALL log the error and provide fallback behavior (skip section, use placeholder text, or notify enseignant)

### Requirement 5: Template Structure Preservation

**User Story:** As an enseignant, I want the final exam to maintain the template's visual structure and formatting, so that my exam looks professional and consistent.

#### Acceptance Criteria

1. WHEN content is injected into a template, THE System SHALL preserve all template formatting: fonts (police), font sizes (taille), margins (margeH, margeV), and page layout
2. WHEN logos are present in the template (logoLeftBase64, logoRightBase64), THE System SHALL include them in the final document at their original positions
3. WHEN institutional headers are defined (universiteFr, institutFr, departementFr, campusText, and Arabic equivalents), THE System SHALL include them in the final document with original formatting
4. WHEN the template specifies language (Français, Arabe, Bilingue), THE System SHALL generate content in the appropriate language(s)
5. WHEN the template style is "long", THE System SHALL use extended formatting with full sections and detailed layouts
6. WHEN the template style is "court", THE System SHALL use compact formatting with condensed sections
7. WHEN the template includes remarks section (blocRemarques), THE System SHALL populate it with template-defined remarks (remarques field)
8. WHEN the final document is generated, THE System SHALL maintain consistent page numbering, section breaks, and table structures from the original template

### Requirement 6: Template-Aware AI Generation

**User Story:** As an enseignant, I want AI generation to be aware of template constraints, so that generated content fits the template structure.

#### Acceptance Criteria

1. WHEN AI generation receives template context, THE AI_Generator SHALL adjust content generation based on template type: final exams generate comprehensive content, cc (control) exams generate shorter assessments, rattrapage (makeup) exams generate alternative content
2. WHEN the template specifies a style (long/court), THE AI_Generator SHALL generate content volume accordingly: long templates receive more detailed questions and sections, court templates receive concise questions
3. WHEN the template specifies language (Français/Arabe/Bilingue), THE AI_Generator SHALL generate content in the specified language(s)
4. WHEN the enseignant specifies duration and total points, THE AI_Generator SHALL generate questions with appropriate point values and complexity to fit within the specified constraints
5. WHEN the template defines exercices array structure, THE AI_Generator SHALL organize content into exercises matching the template's expected structure
6. IF template constraints conflict with generation parameters, THEN THE System SHALL prioritize template constraints and notify the enseignant of adjustments made

### Requirement 7: Exam Draft Creation with Template Reference

**User Story:** As an enseignant, I want to save my generated exam as a draft before final export, so that I can review and modify it later.

#### Acceptance Criteria

1. WHEN the enseignant completes AI generation and template injection, THE System SHALL provide an option to save the exam as a draft
2. WHEN saving a draft, THE System SHALL create a Draft_Exam record containing: title, subject (matiere), level (niveau), duration (duree), total points (noteTotale), sections, and template reference (templateId)
3. WHEN a draft is saved, THE System SHALL store the template ID and header information for later retrieval and modification
4. WHEN the enseignant loads a draft, THE System SHALL restore: the selected template, header information, and AI-generated content
5. WHEN the enseignant modifies a draft, THE System SHALL allow re-injection with the same or different template
6. WHEN the enseignant exports a draft to the exam bank, THE System SHALL generate the final Word document with template injection and create an Exam_Bank_Item record

### Requirement 8: Template Compatibility Validation

**User Story:** As an enseignant, I want the system to validate that AI-generated content is compatible with the selected template, so that injection succeeds without errors.

#### Acceptance Criteria

1. WHEN AI content is generated, THE System SHALL validate that the content structure matches the template's expected format
2. WHEN validating content, THE System SHALL check: number of sections, exercises per section, questions per exercise, and point distribution
3. IF content structure is incompatible with the template, THEN THE System SHALL provide specific error messages indicating which elements are incompatible
4. WHEN incompatibility is detected, THE System SHALL offer options: regenerate content with adjusted parameters, select a different template, or manually adjust content
5. WHEN the enseignant adjusts content manually, THE System SHALL re-validate before allowing injection
6. WHEN validation passes, THE System SHALL confirm compatibility and proceed with injection

### Requirement 9: Template Selection UI Component

**User Story:** As an enseignant, I want an intuitive template selection interface, so that I can easily find and choose the right template.

#### Acceptance Criteria

1. WHEN the template selection interface loads, THE System SHALL display templates organized by type (final, cc, rattrapage) with clear visual separation
2. WHEN templates are displayed, THE System SHALL show: template name, type, language, style, and a thumbnail preview of the template structure
3. WHEN the enseignant hovers over a template, THE System SHALL display a tooltip or expanded preview showing template details
4. WHEN the enseignant clicks "Preview" on a template, THE System SHALL open a modal showing the full template structure with all sections and formatting
5. WHEN the enseignant selects a template, THE System SHALL highlight the selection and enable the "Next" button to proceed to header information
6. WHEN templates are filtered by type or language, THE System SHALL update the display to show only matching templates
7. WHEN no templates match the filter criteria, THE System SHALL display a message indicating no templates are available for the selected criteria

### Requirement 10: Error Handling and Recovery

**User Story:** As an enseignant, I want clear error messages and recovery options when template injection fails, so that I can resolve issues and complete my exam.

#### Acceptance Criteria

1. WHEN template injection fails, THE System SHALL return a descriptive error message indicating the specific cause (missing content, incompatible structure, formatting error, etc.)
2. WHEN an error occurs, THE System SHALL provide recovery options: retry injection, select a different template, manually adjust content, or save as draft for later review
3. WHEN the enseignant retries injection, THE System SHALL attempt the operation again with the same parameters
4. WHEN the enseignant selects a different template, THE System SHALL allow template reselection and re-injection with the new template
5. WHEN the enseignant manually adjusts content, THE System SHALL validate the adjustments before re-injection
6. WHEN an error is logged, THE System SHALL include: error type, timestamp, template ID, enseignant ID, and error details for debugging
7. IF critical errors prevent recovery, THEN THE System SHALL offer to save the current state as a draft and contact support

### Requirement 11: Template Metadata and Configuration

**User Story:** As an enseignant, I want to understand template capabilities and constraints, so that I can choose the right template for my exam.

#### Acceptance Criteria

1. WHEN a template is displayed, THE System SHALL show metadata: template name (nom), type (final/cc/rattrapage), language (Français/Arabe/Bilingue), style (long/court), and creation date
2. WHEN a template is previewed, THE System SHALL display: institutional headers, logos, section structure, optional sections (zoneNomPrenom, zoneGroupe, blocNote, etc.), and formatting specifications
3. WHEN the enseignant views template details, THE System SHALL show: number of sections, exercises per section, question types supported, and point distribution guidelines
4. WHEN the enseignant selects a template, THE System SHALL display constraints: maximum questions, recommended duration, point range, and language requirements
5. WHEN the enseignant generates content for a template, THE System SHALL enforce template constraints and notify the enseignant of any adjustments made

### Requirement 12: Data Flow Between Template Selection and AI Generation

**User Story:** As an enseignant, I want the system to maintain data consistency throughout the workflow, so that all information flows correctly from template selection through final export.

#### Acceptance Criteria

1. WHEN a template is selected, THE System SHALL store the template ID in the current session/context
2. WHEN header information is filled, THE System SHALL store all header values in the current context
3. WHEN AI generation is requested, THE System SHALL pass template ID and header information to the AI_Generator_Service
4. WHEN AI content is generated, THE System SHALL store the content in the current context with template reference
5. WHEN template injection is performed, THE System SHALL use stored template ID, header information, and AI content
6. WHEN a draft is saved, THE System SHALL persist all context data: template ID, header information, and AI content
7. WHEN a draft is loaded, THE System SHALL restore all context data from the database
8. WHEN the enseignant exports to exam bank, THE System SHALL include template reference in the Exam_Bank_Item metadata

### Requirement 13: Template-Specific Content Mapping

**User Story:** As an enseignant, I want AI-generated content to be automatically mapped to template sections, so that content is organized correctly in the final document.

#### Acceptance Criteria

1. WHEN AI content is generated, THE System SHALL organize content into sections matching the template's section structure
2. WHEN the template defines exercices array, THE System SHALL map AI-generated exercises to template exercices with matching structure
3. WHEN mapping exercises, THE System SHALL preserve: exercise number, title, points, and questions
4. WHEN mapping questions, THE System SHALL preserve: question text, type, points, answer lines, and options
5. WHEN the template includes optional sections, THE System SHALL conditionally include mapped content based on template configuration
6. WHEN content cannot be mapped to template structure, THE System SHALL log the mismatch and provide fallback behavior
7. WHEN mapping is complete, THE System SHALL generate a mapping report showing which content was mapped to which template sections

### Requirement 14: Multi-Language Template Support

**User Story:** As an enseignant, I want to generate exams in multiple languages using language-specific templates, so that I can serve diverse student populations.

#### Acceptance Criteria

1. WHEN templates are displayed, THE System SHALL filter by language: Français, Arabe, or Bilingue
2. WHEN the enseignant selects a Français template, THE AI_Generator SHALL generate content in French
3. WHEN the enseignant selects an Arabe template, THE AI_Generator SHALL generate content in Arabic
4. WHEN the enseignant selects a Bilingue template, THE AI_Generator SHALL generate content in both French and Arabic
5. WHEN content is injected into a Bilingue template, THE System SHALL populate both French and Arabic sections with appropriate content
6. WHEN the final document is generated, THE System SHALL maintain language-specific formatting and text direction (RTL for Arabic)

### Requirement 15: Template Modification Workflow

**User Story:** As an enseignant, I want to modify template selection and header information during the workflow, so that I can correct mistakes or try different templates.

#### Acceptance Criteria

1. WHEN the enseignant is in the header information step, THE System SHALL provide a "Change Template" button to return to template selection
2. WHEN the enseignant is in the AI generation step, THE System SHALL provide a "Change Template" button to return to template selection
3. WHEN the enseignant changes templates, THE System SHALL preserve header information if the new template has compatible fields
4. WHEN the enseignant changes templates, THE System SHALL clear AI-generated content and require regeneration
5. WHEN the enseignant returns to template selection, THE System SHALL highlight the previously selected template
6. WHEN the enseignant confirms a new template, THE System SHALL update the context and proceed with the workflow

## Acceptance Criteria Patterns and Testing Strategy

### Pattern 1: Invariants - Template Structure Preservation
- **Property**: After template injection, the final document maintains all template structural elements (logos, headers, sections, formatting)
- **Testing**: Verify that logos, institutional headers, section layouts, and formatting specifications from the template are present in the final document
- **Type**: Property-based test with multiple templates and content variations

### Pattern 2: Round-Trip Properties - Template Selection and Restoration
- **Property**: When a draft is saved with template reference and then loaded, the template selection and header information are restored exactly as saved
- **Testing**: Save draft → Load draft → Verify template ID and header values match original
- **Type**: Property-based test with various template and header combinations

### Pattern 3: Idempotence - Template Injection
- **Property**: Injecting the same content into the same template multiple times produces identical output documents
- **Testing**: Inject content → Generate document → Inject same content again → Verify documents are identical
- **Type**: Property-based test

### Pattern 4: Metamorphic Properties - Content Compatibility
- **Property**: If content is compatible with template A and template B has the same structure, then content should be compatible with template B
- **Testing**: Generate content for template A → Verify compatibility → Switch to template B with same structure → Verify compatibility
- **Type**: Property-based test

### Pattern 5: Error Conditions - Invalid Template Selection
- **Property**: When an invalid or deleted template is selected, the system properly signals an error and provides recovery options
- **Testing**: Attempt to select non-existent template → Verify error message → Verify recovery options available
- **Type**: Integration test with representative error scenarios

### Pattern 6: Confluence - Header Field Independence
- **Property**: The order in which header fields are filled does not affect the final document output
- **Testing**: Fill fields in different orders → Generate documents → Verify documents are identical
- **Type**: Property-based test

### Pattern 7: Model-Based Testing - Template Injection Correctness
- **Property**: Template injection output matches expected structure defined by template specification
- **Testing**: Compare injected document structure against template specification → Verify all fields populated correctly
- **Type**: Integration test with template specification as reference model
